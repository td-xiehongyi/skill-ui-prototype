# 原型交付约定

按项目现有结构保存；无约定时使用以下最小组织：

- `docs/ui-prototype/draft/index.html`：当前可交互草案与本地依赖。
- `docs/ui-prototype/reviews/draft-01/`：交付给用户评审时保存的 HTML、依赖及对应说明快照；每次新交付递增编号，日常编辑不创建快照。已有 Git 等机制能定位并还原同等完整内容时可沿用。
- `docs/ui-prototype/design.md`：当前入口、目标、页面流程、交互与状态、验收条目、确认记录。
- `docs/ui-prototype/versions/v1/`：用户确认时才创建的完整基准快照，包含 HTML、依赖及对应设计说明。后续使用 v2 等新版本。

不提前创建空版本目录。项目已经有版本机制时沿用。快照包含本地资源，避免未来共享 CSS 更新导致旧基准外观变化；远程资源能合法本地保存时再保存，否则记录其可变限制。

交付消息同时给出评审编号和快照入口，确认版从被确认的评审快照生成，不从可能已变化的 `draft/` 生成。不覆盖或复用已交付编号。只有截图时可记录可见区域的视觉依据，不能据此补造完整交互基准；无法找回历史材料时展示新草案并取得对应确认。

## 必须可查的信息

| 信息 | 内容 |
| --- | --- |
| 起点 | 需求或启动记录入口、目标用户、核心任务、本次范围；探索方案或落实设计；探索时的假设与比较任务 |
| 设计状态 | 草案、待用户确认、部分确认、已确认或已替代；评审编号、版本和入口 |
| 页面路径 | 用户从何处开始，主要动作与结果，返回或取消方式 |
| 样式变量 | 颜色、字体、字号、间距、圆角、内容宽度；引用 HTML 的 CSS 变量位置，避免重复维护数值 |
| 状态与交互 | 触发条件、界面反馈、恢复方式；不适用的状态说明理由 |
| 模拟范围 | 哪些数据与操作为模拟，哪些能力尚未实现 |
| 验收条目 | 条件 → 操作 → 预期结果 → 验证方法，覆盖本次核心路径和重要异常 |
| 检查证据 | 应用或浏览器版本、页面可用尺寸（CSS 像素）、缩放、相关系统显示比例及字体加载结果；测试数据入口、状态触发与重置步骤、结果、标明版本和状态的截图入口；未知项与比较限制明示 |
| 确认与变更 | 用户确认依据、日期、来源评审编号；按页面、区域或流程列出确认状态和范围；后续变更原因、旧新版本关系、受影响需求和未决项 |

例如文件整理预览：选中模拟建议 → 点击预览 → 显示原路径、目标路径及冲突提示 → 有冲突的行不能执行，取消返回列表。此条约束界面演示，不证明真实文件操作安全。

部分确认示例：`v1 ← draft-03；列表布局：已确认（用户原话及日期）；冲突弹窗：待确认；整体：部分确认`。未列入确认范围的内容保持待确认。交接和验收逐项引用基准；某项通过不代表整个版本通过。

## 正式开发交接

给出一段可加入现有项目规则的简短约定，是否写入按本次授权与项目约定处理：开发前读取指定的已确认原型版本与交互说明；完成后在实际运行界面按验收条目对照；主要变化先记录差异及理由，并按用户确认结果形成新版本。

总结新发现时区分视觉调整与业务变化。只将已确认的业务变化写入已授权更新的需求或计划；其他内容列为待确认，不顺手重写架构或启动代码实施。
